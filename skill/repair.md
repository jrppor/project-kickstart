# /kickstart · รายการซ่อมโปรเจกต์ที่ตั้งก่อนชุดรุ่นปัจจุบัน

รุ่นรายการซ่อม: 6 (เพิ่มหรือแก้ข้อไหนในไฟล์นี้ ให้เพิ่มเลขนี้ และแก้เลขเดียวกันในข้อ 3 ของ "ขั้นตอนทุกครั้ง" ใน `SKILL.md`)

ตรวจทุกข้อกับ repo ข้อที่ขาดให้ซ่อม บอกผู้ใช้ว่าเพิ่มอะไร แล้ว commit แยก จบแล้วเขียน `รุ่นซ่อม: 6` ต่อท้ายบรรทัดหัวของ `docs/progress.md`

- `CLAUDE.md` ไม่มีหัวข้อ "ลำดับงาน" หรือ "เตรียม worktree" → คัดลอกจาก `KIT/templates/CLAUDE.md` แล้วเติมค่าจริงของโปรเจกต์
- `.claude/settings.json` ไม่มี hook `SubagentStop` หรือ `verify.mjs` ไม่มีโหมด `subagent-stop` → agent ใน worktree ไม่ผ่านด่าน
  ให้คัดลอกส่วนท้ายของ `KIT/templates/.claude/hooks/verify.mjs` (ตั้งแต่ `const OUTPUT_TAIL_LINES` ลงไป) และ hook จากแม่แบบ settings โดยคง `CHECKS`/`FORMATTERS` ของโปรเจกต์ไว้
- ไม่มี `.worktreeinclude` แต่มี `.env` ที่ git ignore → สร้างจากแม่แบบ
- Edit/Write ใน auto mode ช้าครั้งละหลายวินาที (ดู `permissionDecision` ของ Edit ใน transcript ถ้าเป็น `classifier`) และ `~/.claude/settings.json` ไม่มีกฎ `Edit(//...)` ครอบโฟลเดอร์ของโปรเจกต์ → เสนอตั้งกฎระดับผู้ใช้ตามขั้น 1 ข้อ 4 ของ playbook (ถามโฟลเดอร์ บอกข้อแลก รอคำตอบตกลง ถ้าระบบไม่ให้แก้ให้บอกบรรทัดที่ต้องเพิ่ม) · `Edit(/**)` ใน `.claude/settings.json` ของโปรเจกต์ไม่ต้องเพิ่ม (ใช้ได้เฉพาะเมื่อโฟลเดอร์ trust แล้ว)
- หัวข้อ "เตรียม worktree" ไม่มีข้อห้ามใช้คำสั่งในรายการ `ask` หรือข้อห้ามสร้างข้อมูลทดสอบใน DB ของ dev → เพิ่มจากแม่แบบ
- `FORMATTERS` ตัวที่เรียกของใน `node_modules` หรือ venv แต่ไม่มี `needs` → เพิ่ม `needs` (ไม่งั้น hook ล้มทุกครั้งที่ agent แก้ไฟล์ใน worktree ที่ยังไม่ได้ติดตั้ง)
- `verify.mjs` ไม่มี `CLAUDE_MD_LIMIT` → คัดลอกส่วนท้ายแบบเดียวกับข้อบน · CLAUDE.md ไม่มีตาราง "ก่อนแตะเรื่องไหน อ่านอะไร" → เพิ่มจากแม่แบบ ถ้าเกินเพดานให้ทำตาม "ย้ายรายละเอียดออกจาก CLAUDE.md" ใน P9
- `verify.mjs` ไม่มี `PROGRESS_LIMIT` (หรือ `LENGTH_LIMITED_DOCS`) → คัดลอกส่วนท้ายแบบเดียวกับข้อบน · `docs/progress.md` เกิน 8,000 ตัวอักษร → ทำตามพรอมต์ "ย้ายประวัติออกจาก docs/progress.md" ใน P9 (ตัดมาทั้งก้อนไป `.scratch/<ฟีเจอร์>/log.md` ห้ามสรุปใหม่ พิสูจน์ด้วยโทเคนใน backtick)
- ต้องยกระบบเพื่อดูผล (เว็บ API worker mobile desktop) แต่ไม่มี `.claude/skills/run-*/` หรือ CLAUDE.md ไม่มีบรรทัด "การตรวจบนระบบจริง" → ทำตาม **P3c** (สคริปต์ยกระบบที่คัดลอกต่อใบงานใน `.scratch/` รวมเข้าสกิลนั้น)
- **`.claude/settings.json` ห้ามเขียนเอง** auto mode ปฏิเสธการแก้ไฟล์สิทธิ์ของตัวเองทุกครั้ง (Self-Modification) และห้ามหาทางอ้อม
  ให้เขียนไฟล์ที่รวมแล้ว (ของเดิมทั้งหมด + ส่วนที่ขาดจากแม่แบบ) ไว้ที่ `.scratch/settings.proposed.json` แล้วบอกผู้ใช้ว่าเพิ่มอะไร
  พร้อมคำสั่งเดียวให้รันเอง: `mv .scratch/settings.proposed.json .claude/settings.json` ห้าม commit ไฟล์ proposed
  หลังผู้ใช้ย้ายแล้ว ตรวจว่าเป็น JSON ที่ถูกต้องแล้ว commit `.claude/settings.json` · hook ใหม่ทำงานเมื่อเปิด session ใหม่
  ซ่อมข้ออื่นต่อได้โดยไม่ต้องรอ
- `docs/progress.md` ขาดสิ่งที่รูปแบบใน `progress-format.md` เพิ่มภายหลัง → เติมเฉพาะที่ขาด ห้ามจัดไฟล์ใหม่ทั้งไฟล์:
  บรรทัด `3c` ในขั้นตั้งต้น (ติ๊กถ้ามี `.claude/skills/run-*/` แล้ว หรือเขียนว่าข้ามถ้าไม่ต้องยกอะไรขึ้นมา) ·
  วันที่ merge ในแถวของฟีเจอร์ที่ merge แล้ว (อ่านจาก `git log -1 --format=%as <commit>`) ·
  หัวข้อ "รอตัดสิน" พร้อมบรรทัด "ทบทวนโครงสร้างล่าสุด" (ถ้าไม่มีหลักฐานว่าเคยทบทวน เขียน "ยังไม่เคย" แล้วถามผู้ใช้ยืนยัน)
  ถ้าเติมแล้วไฟล์จะเกินเพดาน 8,000 ตัวอักษร ให้ทำพรอมต์ "ย้ายประวัติออกจาก docs/progress.md" ใน P9 ก่อน แล้วค่อยเติม
- `verify.mjs` ไม่มี `CHECK_TIMEOUT_MS` หรือไม่มี `CHECK_RUNNER` (รุ่นก่อน 2026-11-11) → ด่านมีบั๊กที่แก้แล้วในแม่แบบ: ด่านแดงที่ output มีตัวเลขเวลาบล็อกวนไม่จบ · คลังที่ยังไม่มี commit แรกทำให้ด่านพัง · formatter ที่หาโปรแกรมไม่เจอบล็อกทุกการแก้ไฟล์ · คำสั่งที่ค้างไม่มีเวลาสูงสุด (และรุ่นแรกของ timeout ฆ่าได้แค่ shell ตัวหุ้ม โปรเซสลูกบน Windows ค้างต่อ จึงมี `CHECK_RUNNER` ที่ฆ่าทั้งต้นไม้)
  เทียบส่วนท้ายของโปรเจกต์กับแม่แบบ (ตั้งแต่ `const OUTPUT_TAIL_LINES` ลงไป) ด้วย `diff` ก่อนทำอะไร:
  - ส่วนท้ายเหมือนแม่แบบรุ่นเก่า (ต่างแค่ที่แม่แบบแก้) → คัดลอกส่วนท้ายแบบเดียวกับข้อบน โดยคง `CHECKS` และ `FORMATTERS` ของโปรเจกต์ไว้ ถ้าโปรเจกต์ปรับเพดานใน `CLAUDE_MD_LIMIT` หรือ `PROGRESS_LIMIT` ไว้ ให้คงค่าที่ปรับ
  - ส่วนท้ายต่างจากแม่แบบด้วยเหตุอื่น (เช่น โปรเจกต์วัดเพดานความยาวผ่านโมดูลของตัวเอง) → ห้ามทับทั้งก้อน ให้ย้ายเฉพาะการแก้บั๊กเข้าไปทีละจุด (`CHECK_TIMEOUT_MS` กับ `CHECK_RUNNER` · hash ของผลซ้ำจากชื่อด่านกับคำสั่งที่ล้ม ไม่ใช่จาก output · `currentHead()` · ข้าม formatter เมื่อ `ENOENT`) แล้วบอกผู้ใช้ว่าส่วนไหนต่างจากแม่แบบ
  - ตั้ง `CHECK_TIMEOUT_MS` ให้ต่ำกว่า `timeout` ของ hook `Stop` ใน `.claude/settings.json` (ค่าแม่แบบ 120 วินาที ถ้าด่านมี build ช้า เช่น `dotnet build` ทั้ง solution ให้ปรับขึ้นแต่ไม่เกินเวลาของ hook ไม่งั้นถูกตัดเงียบๆ)
  - `FORMATTERS` ที่เรียกของใน `node_modules` หรือ venv ต้องมี `needs` (ตรวจที่ตัว `FORMATTERS` เอง ไม่ใช่นับคำว่า `needs` ทั้งไฟล์ เพราะ `CHECKS` ก็ใช้คำนี้)
  จากนั้นทำสามอย่างก่อน commit: รัน `node --check .claude/hooks/verify.mjs` · ใส่ `install: "<คำสั่งติดตั้ง>"` ในชุดตรวจที่มี `needs` และไม่ใช้ npm (ไม่ใส่ ข้อความจะบอกแค่ "ให้ติดตั้ง dependency") · รันเทสต์ด่านตามข้อล่าง (ถ้ายังไม่ได้คัดลอก ให้ทำข้อนั้นก่อน) หรือถ้าไม่ทำเทสต์ รัน `echo '{}' | node .claude/hooks/verify.mjs stop` หนึ่งครั้งให้จบด้วย exit 0 หรือ 2 พร้อมรายงานด่านตามปกติ ไม่ใช่ stack trace
- มี `.claude/hooks/verify.mjs` แต่ไม่มี `scripts/verify.test.mjs` → คัดลอกจาก `KIT/templates/scripts/verify.test.mjs` ตรงตัว ห้ามแก้ แล้วรัน `node --test scripts/verify.test.mjs`
  - ผ่านทั้ง 5 ข้อ → เพิ่ม `.claude/hooks` เข้า `area` ของชุดตรวจสคริปต์ใน `CHECKS` (ถ้ามี) เพื่อให้แก้ด่านแล้วเทสต์รันให้ · ถ้าไม่มีชุดตรวจนั้น ให้เสนอผู้ใช้เพิ่มจากตัวอย่าง `tooling` ในแม่แบบ ไม่เพิ่มเอง
  - แดง → แยกสาเหตุก่อน: ส่วนท้ายของด่านต่างจากแม่แบบด้วยเหตุอื่น หรือบั๊กจริงของด่าน ห้ามแก้เทสต์ให้ผ่านโดยไม่บอกผู้ใช้ ถ้าต้องปรับเทสต์ให้เข้ากับโปรเจกต์ บอกว่าปรับอะไรและเพราะอะไร
  - ทดสอบบน Windows เท่านั้น ถ้ารันบน macOS หรือ Linux แล้วแดงข้อ "คำสั่งค้าง" ให้รายงานผู้ใช้ อย่าเดาแก้
