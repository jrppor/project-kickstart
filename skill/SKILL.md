# /kickstart

ผู้ใช้ไม่ต้องคัดลอกพรอมต์จาก `02-prompts.md` อีก สกิลนี้อ่านสถานะของ repo แล้วทำขั้นถัดไปให้
ถ้าขั้นนั้นต้องใช้สกิลที่ผู้ใช้ต้องพิมพ์เอง ให้จบเทิร์นด้วยกล่องบอกคำสั่งที่ต้องพิมพ์

## แหล่งข้อมูล

ชุดอยู่ที่ `C:\Coding\project-kickstart` (เรียกว่า KIT) อ่านเฉพาะส่วนของขั้นที่กำลังทำ ไม่ต้องอ่านทั้งไฟล์

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `KIT/01-playbook.md` หัวข้อ "ขั้นที่ N" | เป้าหมาย เกณฑ์ "เสร็จ" และกับดักของขั้น |
| `KIT/02-prompts.md` หัวข้อ "PN" | คำสั่งของขั้น ให้ทำตามเหมือนผู้ใช้ส่งมาเอง ("ผม" ในพรอมต์คือผู้ใช้) และแทน `<...>` ด้วยข้อมูลจริงจาก repo |
| `KIT/03-project-shapes.md` | แถวของรูปแบบโปรเจกต์นี้ |
| `KIT/templates/` | ไฟล์แม่แบบของขั้นที่ 1 |

สถานะของโปรเจกต์อยู่ที่ `docs/progress.md` ใน repo (รูปแบบอยู่ท้ายไฟล์นี้)

## ขั้นตอนทุกครั้ง

1. **ตรวจที่อยู่ของ session** ถ้า session ไม่ได้เปิดในโฟลเดอร์โปรเจกต์ (ไม่มี `.claude/` ของโปรเจกต์ หรือ cwd เป็นโฟลเดอร์แม่) ให้เตือนว่า hooks จะไม่ทำงาน
   ยกเว้นขั้นที่ 0 ที่ยังไม่มี repo
2. **หาขั้นปัจจุบัน** อ่าน `docs/progress.md` ก่อน ถ้าไม่มี ให้อนุมานจากไฟล์ตามตารางด้านล่าง
   แล้วสร้าง progress.md จากสิ่งที่พบ ข้อที่ไม่แน่ใจ (เช่น ticket ไหนเสร็จแล้ว) ให้เขียนว่า "คาดว่า" แล้วถามผู้ใช้ยืนยันก่อนทำต่อ
   ถ้า `CLAUDE.md` ของโปรเจกต์ยังไม่มีหัวข้อ "ลำดับงาน" ให้คัดลอกหัวข้อนั้นจาก `KIT/templates/CLAUDE.md` ไปเพิ่ม (โปรเจกต์ที่เริ่มก่อนมีสกิลนี้จะไม่มี)
3. **เทียบ progress กับ repo จริง** ถ้าไม่ตรงกัน (เช่น progress บอกขั้น 5 แต่มี issues ครบแล้ว) ให้เชื่อ repo แล้วแก้ progress
   ถ้า `git worktree list` มี worktree ของ agent (`.claude/worktrees/agent-*`) อาจมี `/implement-spec` หรือ session อื่นกำลังทำ ticket อยู่
   ให้ถามผู้ใช้ก่อนแนะนำ ticket ที่อาจซ้ำ
4. **ทำขั้นนั้น** ตามตาราง "ใครทำ" ด้านล่าง
5. **อัปเดต `docs/progress.md`** ทั้งเครื่องหมายขั้นและหัวข้อ "ขั้นถัดไป"
6. **จบเทิร์นด้วยกล่องขั้นถัดไป** (รูปแบบด้านล่าง) เสมอ

## กติกา

- อนุมัติทุกจุดต้องมาจากผู้ใช้ในแชต ห้ามอนุมานว่า "น่าจะโอเค"
- ห้ามแก้ไฟล์ใน KIT จากสกิลนี้ ถ้าเจอว่าพรอมต์หรือแผนมีปัญหา ให้เสนอใน `KIT/ideas.md` ตามแบบฟอร์ม
- งานขนาดเล็ก (1–3 วัน): ขั้น 0 แบบย่อ → 1 → 3 แล้วบอกให้ใช้ `/tdd` ข้ามขั้น 2, 2.5, 4, 5
- ถ้ามีหลายฟีเจอร์ค้าง ให้ถามว่าจะทำฟีเจอร์ไหน
- commit ตามที่พรอมต์ของขั้นบอก รวม `docs/progress.md` ไปใน commit เดียวกับงานของขั้นนั้น
