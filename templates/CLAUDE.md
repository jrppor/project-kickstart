## ด่านตรวจอัตโนมัติ (`.claude/hooks/verify.mjs`)

- ก่อนจบเทิร์น (และก่อน agent ย่อยใน worktree ส่งงาน) ด่านรันเฉพาะส่วนที่ไฟล์เปลี่ยน: `<โฟลเดอร์>/` รัน `<...>`
- ด่านแดงต้องแก้ที่ต้นเหตุ ห้ามปิดเช็ก ห้าม skip เทสต์ ห้ามแก้เทสต์ให้ผ่านแทนการแก้โค้ด ถ้าแก้ไม่ได้ให้บอกผู้ใช้ว่าติดอะไร
- ด่านไม่ได้รัน `<เทสต์ที่ช้า เช่น integration, e2e, build เต็ม>` ให้รันเองก่อน commit งานที่แตะส่วนนั้น
- การตรวจบนระบบจริง (ตั้งในขั้นที่ 3 · library หรือ CLI ที่ไม่ต้องยกอะไรขึ้นมาให้ลบข้อนี้): ยกระบบ ล็อกอิน เตรียมข้อมูล และถ่ายภาพด้วยสกิล `/run-<ชื่อโปรเจกต์>` (`.claude/skills/run-<ชื่อโปรเจกต์>/`) `<"และ e2e อยู่ที่ <โฟลเดอร์> ticket ที่มีหน้าจอเพิ่มเส้นทางของตัวเอง" ถ้ามี>`
  สคริปต์ใน `.scratch/<feature>/verification/` มีได้เฉพาะการตรวจที่เป็นของใบนั้น เจอสิ่งที่ขวางการยกระบบ ล็อกอิน หรือเตรียมข้อมูล
  ให้แก้สกิลใน commit ของใบนั้นเอง (อยู่ในขอบเขตของทุกใบ) ห้ามเขียนสคริปต์ยกระบบแยกใน `.scratch/`

## เตรียม worktree (agent ย่อยและ `claude --worktree`)

<!-- เติมในขั้นที่ 3 ด้วยคำสั่งที่รันผ่านจริง -->
- `.env` ถูกคัดลอกมาให้แล้วผ่าน `.worktreeinclude` ไม่ต้องสร้างใหม่
- ติดตั้ง dependency ก่อนเริ่มงาน: `<เช่น npm --prefix ui ci>`
- ใช้พอร์ตของตัวเอง ห้าม kill process ตามพอร์ต (อาจเป็นของ agent อื่นหรือของผู้ใช้)
- เทสต์ช้าที่ใช้ DB/Redis: `<ตั้งชื่อ DB ของเทสต์ต่อ worktree อย่างไร · "แยกให้เองแล้ว (testcontainers)" · หรือ "ห้ามรันพร้อม agent อื่น">`
- ลองด้วยมือหรือบนเบราว์เซอร์ด้วย DB/Redis ของตัวเองแบบเดียวกับเทสต์ ห้ามสร้างผู้ใช้หรือข้อมูลทดสอบใน DB ของ dev
- เขียนไฟล์ด้วย Write/Edit ไม่ใช้ heredoc หรือคำสั่งหลายตัวต่อกันใน Bash (ตัวกันของ worktree จะปฏิเสธ)
- ห้ามใช้คำสั่งในรายการ `ask` ของ `.claude/settings.json` (เช่น `rm -rf`, `Remove-Item -Recurse`, `git reset --hard`, `git clean`)
  agent เบื้องหลังจะค้างรอผู้ใช้กดอนุญาตโดยไม่มีใครเห็น ไฟล์ชั่วคราวให้เขียนลงโฟลเดอร์ชื่อใหม่ทุกรอบแทนการลบของเดิม
  ถ้า branch ไม่ได้แตกจากจุดที่ควรเป็น ให้หยุดแล้วรายงาน ไม่ reset เอง

## ลำดับงาน (`docs/progress.md`)

- โปรเจกต์นี้เดินตามขั้นของ project-kickstart สถานะอยู่ใน `docs/progress.md` ใช้ `/kickstart` เพื่อทำขั้นถัดไป
- จบงานของขั้นใด (รวมงานจากสกิลที่ผู้ใช้พิมพ์เอง เช่น `/to-spec`, `/to-tickets`, `/implement`) ให้อัปเดต `docs/progress.md`
  แล้วปิดคำตอบด้วยคำสั่งถัดไปที่ผู้ใช้ต้องพิมพ์ หรือบอกให้พิมพ์ `/kickstart`
- ticket ใน `.scratch/` ที่ทำเสร็จและเทสต์ผ่านแล้ว ให้แก้บรรทัด Status เป็น `done` และใส่ trailer `Ticket: <feature>/<NN>` ใน commit ของงาน
- จบแต่ละขั้นหรือแต่ละ ticket ให้ commit เองโดยไม่ต้องถาม (ห้าม push จนกว่าผู้ใช้สั่ง)
- งานที่ทำให้ CLAUDE.md, ADR หรือเอกสารใน `docs/` (รวม `docs/guides/`) ผิด ต้องแก้เอกสารนั้นใน commit เดียวกัน (GEN-4)
